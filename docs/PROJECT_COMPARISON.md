## 本轮落实

- 同一账号最多处理一条接口生成请求，忙碌时选择其他可用账号。
- 同一账号默认至少间隔 2 秒开始下一条请求，可在设置中调整。
- 同一次请求的重试不重复选中已经尝试过的账号，避免围着同一失效会话重试。
- 收到 429 后暂停使用该账号，默认至少 300 秒；收到有效的 `Retry-After` 或更晚的已知额度恢复时间时，等待更久。
- 403 暂停使用，401 或明确的 session 失效标记为失效；一般 400 输入错误不会误伤账号。
- 冷却时间保存到数据库，重启不会提前把受限账号放回轮询。
- 支持手动暂停与恢复，暂停不删除 sessionKey，也不取消已经开始的请求。重复导入账号不会清除暂停或休息时间。
- 设置写到临时文件后替换原文件。写入失败不会改变内存中的运行设置，文件权限为仅当前用户可读写。
- 首页显示近 24 小时成功率和成功请求的平均耗时，数据来自保留的调用记录。
- 账号选择页加入常用账号、搜索与用量条。常用偏好只在当前浏览器保存。
- 主界面使用短句，接口说明默认收起，减少术语和括号补充。

## 账号保护的边界

这些措施控制请求节奏、减少无效重试和并发碰撞，不保证账号不会受限。网页版接口仍受账号权限、用量、网络、上游协议变化及服务方规则影响。

保持登录环境稳定、不要同时在多个位置密集使用同一账号、尊重上游返回的等待时间，比频繁切换身份和强行重试更适合作为默认运维策略。本轮没有加入伪造验证结果、自动注册或自动解封。

Anthropic 官方 API 文档说明，遇到带 `retry-after` 的 429 应按该时长等待：[Rate limits](https://platform.claude.com/docs/en/api/rate-limits)。这里将“尊重等待时间”用于网页代理的错误处理；并不假定网页版与官方 API 的额度规则完全相同。

## 未直接移植

持久会话、完整 Cookie 导入、自动更新模型和 OAuth 续期涉及不同的授权与会话生命周期。没有真实账号验证时不宜改动已确认可用的 sessionKey 导入流程。当前继续保留原导入方式。

所有新增功能按本项目结构自行实现，没有复制外部项目源码。ClewdR 使用 AGPL-3.0；Aurora 等部分仓库没有明确的许可证元数据，因此本轮只参考公开功能和交互思路。
